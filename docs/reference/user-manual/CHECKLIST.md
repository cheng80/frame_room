# 설명서 제작 검수표

결과는 `PASS` / `FAIL` / `NOT_RUN` / `N/A` 중 하나로 기록한다. `N/A`는 선택 배포 기능 등 적용되지 않는 이유가 있을 때 사용한다. 막힌 브라우저 검사는 `NOT_RUN`으로 남긴다.

## 내용과 구조

- [ ] 퀵스타트와 상세 설명서가 구분되어 있다. [U01–U03]
- [ ] 처음 사용자가 입력부터 저장·내보내기까지 실제로 따라갈 수 있다.
- [ ] 각 단계에 현재 화면, 클릭할 위치, 필요한 값, 정상 결과가 있다.
- [ ] 기존 문서의 목차·장 구성·배치를 보존하고 필요한 변경 이유를 기록했다. [U04]
- [ ] 실제 버튼명·기본값·저장 위치·메뉴 위치가 최신 제품과 맞는다. [U10]
- [ ] 자동 검사·수동 승인·저장·출력 상태를 정확히 구분했다.
- [ ] 참고 예제의 수량·품질을 제품의 보장이나 현재 기본값으로 오해하게 쓰지 않았다.

## 글자와 레이아웃

- [ ] 본문 자체가 읽기 쉽고 이미지 확대에 의존하지 않는다. [U05]
- [ ] 본문·단계·FAQ·표·목차·메뉴·버튼·캡션의 실제 계산된 글자 크기를 확인했다.
- [ ] 권장 기준과 다른 작은 글자가 있으면 이유를 기록하고 필수 정보를 담지 않는지 확인했다.
- [ ] `320px`·`390px`와 데스크톱 화면에서 문장이 잘리거나 전체 페이지가 가로로 넘치지 않는다.
- [ ] 브라우저 `200%` 확대에서도 필수 정보와 버튼을 사용할 수 있다.
- [ ] 글자를 줄이는 대신 줄바꿈·열 수·목차 배치로 공간을 조정했다.
- [ ] 표·코드의 가로 스크롤은 필요한 영역 안에 한정된다.

## 이미지·확대·패닝

- [ ] 현재 제품 화면의 원본 해상도·출처·캡처 상태를 기록했다.
- [ ] 확대 원본의 노드명·버튼명·수치가 선명하다. [U09]
- [ ] 실제 캡처, PDF 렌더, AI 원본, 처리 결과, 합성 시험 자료를 구분했다. [P02]
- [ ] 이미지 자체와 별도 버튼 모두 팝업을 연다. [U06]
- [ ] 첫 진입은 전체 이미지가 보이고 제목·캡션이 유지된다.
- [ ] 확대·축소·배율 표시·원본 보기·화면 맞춤 복귀가 동작한다. [U07]
- [ ] 첫 확대가 현재 맞춤 크기보다 실제로 커진다.
- [ ] 확대 상태에서 마우스 가로·세로 패닝이 동작하고 드래그 종료 후 상태가 풀린다. [U08]
- [ ] 키보드나 스크롤로도 이미지의 필요한 부분에 접근할 수 있다.
- [ ] 좁은 화면·긴 제목에서도 확대 조작과 닫기 버튼이 유지된다.
- [ ] Escape·닫기·초점 복귀가 동작한다. 제공하는 경우 배경 클릭 닫기도 확인했다.
- [ ] 이미지 위 번호 안내와 팝업 열기가 서로 오작동하지 않는다.
- [ ] 다시 열었을 때 배율·스크롤·패닝 상태가 일관되다.

## 탐색·체험·배포

- [ ] 목차·검색·FAQ·단축키 링크가 실제 내용으로 이어진다.
- [ ] 예제 체험은 사용자 프로젝트 변경이나 유료 요청을 일으키지 않는다.
- [ ] 애니메이션은 기본 정지이며 탭 숨김·인쇄 시 정지한다.
- [ ] 체크리스트가 실제 제품 승인 상태처럼 표시되지 않는다.
- [ ] 복사 기능 성공·권한 거부 시 대체 안내를 확인했다. 미실행이면 따로 기록한다.
- [ ] JavaScript 없이도 기본 본문·목차·이미지를 읽을 수 있다.
- [ ] 원본을 수정해 빌드했으며 생성 HTML에만 남는 변경이 없다.
- [ ] 중복 ID·내부 앵커·교차 링크·이미지 경로를 검사했다.
- [ ] 오프라인 배포 시 ZIP 무결성, 압축 해제 후 상대 경로와 `file://` 읽기를 확인했다.
- [ ] 인쇄 제공 시 본문·캡션 크기, 표 잘림, FAQ 펼침, 정지 이미지, 페이지 나눔을 확인했다.
- [ ] 배포본을 제공한다면 실제 배포 자산과 검증한 산출물이 일치한다.
