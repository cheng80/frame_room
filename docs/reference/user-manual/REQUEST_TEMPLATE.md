# 다른 프로젝트에 전달할 요청문

[제작 기준](README.md) · [사용자 지시 출처](USER_REQUESTS.md) · [검수표](CHECKLIST.md)

아래 요청문에서 대괄호 부분만 현재 프로젝트에 맞게 바꾼다. 이 문서 묶음을 함께 전달한다. 기존 설명서가 있으면 먼저 읽고 구조를 유지한다.

---

`[프로젝트명]`의 HTML 사용 설명서를 제작·갱신해 주세요.

- 프로젝트 경로: `[프로젝트 절대 경로]`
- 기존 설명서: `[경로 또는 URL / 없으면 신규]`
- 대상 사용자와 첫 성공 결과: `[누가 무엇을 처음 완성해야 하는지]`
- 기준 제품 버전: `[버전 또는 현재 작업 트리를 확인해 기록]`
- 문서 저장 위치: `[프로젝트 docs 및 공개 설명서 경로]`
- 필요한 배포 형태: `[앱 내 열기 / 웹 / 오프라인 ZIP / 인쇄·PDF 중 해당 항목]`

첨부한 프레임룸 설명서 제작 기준을 참고하되, 제품의 실제 화면·버튼명·작업 순서에 맞춰 작성해 주세요. 제품 판매용 설명서처럼 실제 화면과 단계별 조작, 정상 결과, 막혔을 때 확인할 내용을 함께 넣어 주세요. 퀵스타트와 상세 설명서는 구분해 주세요.

기존 설명서의 목차·장 구성·배치는 유지해 주세요. 읽기 쉬워지도록 글자·줄간격·여백·줄바꿈을 조정하고, 전체 구조 변경이 필요하면 변경 이유와 범위를 먼저 구체화해 주세요.

가독성은 본문과 이미지 각각 확인해 주세요. 본문은 데스크톱 17–18px, 모바일 16–17px, 캡션은 14px 이상, 메뉴·버튼은 15–16px를 기본안으로 삼아 주세요. 이는 참고용 수치이며, 현재 프로젝트의 명시적 기준이 있으면 그 기준과 사용자 요구를 함께 확인해 주세요. 공간이 좁다는 이유로 필수 글자를 10–12px로 줄이지 말고 배치를 조정해 주세요. 브라우저 확대도 막지 마세요.

이미지는 다음 조건을 충족해 주세요.

1. 실제 최신 UI를 선명하게 캡처하고, 이미지 속 글자까지 읽을 수 있는 원본을 사용합니다.
2. 이미지 자체 클릭과 별도 확대 버튼 모두 큰 팝업을 엽니다.
3. 팝업에서 확대·축소, 배율 확인, 화면 맞춤, 원본 보기, 닫기를 제공합니다.
4. 확대된 이미지는 마우스로 잡아 가로·세로로 이동할 수 있어야 합니다.
5. Escape·키보드 조작·초점 복귀를 확인하고, 좁은 화면에서도 닫기·확대 조작이 가려지지 않게 합니다.
6. 저해상도 파일을 늘려 저장한 결과를 고해상도 캡처라고 표시하지 않습니다.

목차·검색·FAQ·단축키·진행 체크·체험은 이해에 도움이 되는 항목만 적용해 주세요. 체험이 실제 프로젝트를 수정하거나 유료 생성 요청을 실행하지 않게 하고, 실제 생성·가져온 원본·처리 결과·합성 시험 자료를 구분해 주세요. 자동 재생보다 명시적 재생 버튼을 사용해 주세요.

오프라인 배포를 선택했다면 기본 읽기에 외부 CDN·서버·로그인·폰트를 요구하지 않게 하고, 압축 해제 후 HTML을 직접 열어 확인해 주세요. 인쇄·PDF가 범위에 있다면 작은 글자, 잘린 표, 접힌 FAQ, 정지되지 않은 애니메이션을 점검해 주세요.

원본 콘텐츠·스타일·동작·생성기를 함께 관리하고, 생성된 HTML만 수정해 다음 빌드에서 덮어써지는 변경을 만들지 마세요. 앱 화면이 바뀌면 설명서 화면과 절차도 함께 갱신해 주세요.

브라우저 검증은 프로젝트 규칙을 따르며 사용자 마우스와 작업 창을 가로채지 마세요. 프레임룸 작업에서는 기존 ego TaskSpace를 재사용하고 Chrome·별도 Chromium을 설치하거나 실행하지 않습니다. 브라우저 검증이 막히면 정적 검사 결과와 미실행 항목을 구분해 주세요.

완료 시 설명서 경로, 실제 확인한 화면 크기와 기능, 빌드·링크·배포 검사 결과, 남은 제한을 검수표에 기록해 주세요. 과거 다른 작업의 커밋·push·배포 승인을 이번 작업의 승인으로 사용하지 마세요.
