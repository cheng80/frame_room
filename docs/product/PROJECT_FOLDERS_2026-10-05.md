# 프로젝트 폴더와 SQLite 관리

> 2026-10-06 자료 정리: 아래 조사·실험의 원본, 비교 결과와 전용 스크립트는 사용자 요청으로 삭제했다. 제품 결정·구현 기록은 보존하며 과거 경로를 현재 실행 가능한 자료로 해석하지 않는다.

**후속 정리 반영:** 아래 ‘실제 데이터 적용’과 증거 경로는 전환·검증 당시 기록이다. 이후 사용자 요청으로 이전 공용 중복 파일, 임시 복제본, `app-before.sqlite3`를 포함한 `.data/experiments/project-folders-20261005/` 검수 자료를 정리했다. 등록된 5개 프로젝트 폴더와 원본/이력은 보존했다. 현재 보존 범위와 작업 재개는 [HANDOFF.md](HANDOFF.md)를 따른다.

## 저장 구조와 동작

기본 경로는 `.data/projects/<이름>--<projectId>/`이며 생성 화면에서 다른 부모 폴더를 선택하거나 직접 입력할 수 있다. 폴더 안에 `project.json`, `project.sqlite3`, `assets/`, `videos/`, `jobs/`, `outputs/`를 둔다. 프로젝트 SQLite에는 현재 상태·모든 저장 이력·자산/영상 메타데이터·작업/이벤트/출력·묶음 접수 정보·미게시 원본의 소유 관계를 저장한다. 리소스 경로는 폴더 기준 상대 경로다.

공용 `app.sqlite3`는 등록 목록과 실행 인덱스/캐시다. 변경을 커밋할 때 동기화 대기 기록을 남기고, 원본 파일 복사와 프로젝트 SQLite의 원자적 교체를 완료한 뒤 성공을 응답한다. 실패하면 503과 `storage.syncPending`을 반환하며 공용 인덱스의 보류 데이터는 유지한다. 재시작이나 같은 폴더/이동한 폴더 열기로 반영을 재개한다. 화면은 이를 ‘저장됨’ 대신 ‘폴더 저장 보류’로 표시한다.

**목록에서 제거**는 등록·관련 인덱스·브라우저 초안을 제거한다. 프로젝트 폴더와 파일은 유지하며 ‘프로젝트 폴더 열기’로 동일 ID와 이력을 복원한다. 복제 프로젝트의 리소스는 실제 파일로 복사하여 독립성을 유지한다. ZIP 백업 복원은 기존처럼 현재 상태를 새 ID로 복원하는 별도 기능이다.

**없는 폴더 정리**는 미리 확인한 이름·경로를 보여준 뒤 실행한다. 트랜잭션에서 ID·저장 버전·등록 경로·폴더 부재·진행 작업을 재확인한다. 대상 중 하나라도 조건이 바뀌면 전체 정리를 거부한다. 프로젝트/이력/작업/이벤트/출력/소유 관계/묶음 캐시와 다른 프로젝트가 쓰지 않는 자산·영상 인덱스를 정리한다. 실제 파일은 삭제하지 않는다. 루트 폴더가 존재하는 내부 손상 프로젝트는 누락 정리 대상이 아니다.

실행 중 폴더가 사라지면 그 프로젝트 작업만 중단하고 자식 프로세스를 정리한다. 다른 프로젝트 작업은 계속 처리한다. 기존 외부 요청의 재전송 차단과 outbox를 유지한다. 폴더 열기 자체는 가져온 대기/실행 작업을 자동 실행하지 않는다.

## 실제 데이터 적용

- 기존 5개 프로젝트를 개별 폴더로 전환했다.
- 프로젝트 상태·저장 이력 91개·작업 33개·이벤트 153개·출력 기록 87개·export 기록 3개는 원본과 동일하다.
- 기존 원본/영상/출력 480개 파일, 86,379,548바이트의 해시를 전환 전후 확인했다. 이전 공용 물리 파일도 보존했다.
- 목록 제거/정리 과정에서 어떤 등록 프로젝트에도 속하지 않는 자산 인덱스 48개가 정리됐다. 등록된 모든 프로젝트의 현재·과거·미게시 원본은 유지했다. 물리 파일은 지우지 않았다.
- 공용 SQLite 전환 전 백업: `.data/experiments/project-folders-20261005/app-before.sqlite3`.
- 최종 현재 프로젝트 5개, 누락 등록 0개, 동기화 보류 0개. API/worker 재시작 후 ready 상태를 확인했다.

## 실제 폴더만 복사한 검증

`Grok 영상 · 실제 보행 검수` 폴더를 별도 경로로 복사해 새로운 공용 인덱스에서 열었다. 저장 버전 26과 이력 26개, 영상 및 이전 출력 56개를 읽고 해시를 확인했다. 복사본에서 캐릭터 이름을 편집한 뒤 최종 28프레임 동작을 bake했다. 원래 결과와 아틀라스 크기 448×512 및 전체 RGBA 바이트가 같았다. 원래 프로젝트는 버전 26으로 유지했다. bake의 `needs_review`는 기존 수동 검수 미승인 상태를 그대로 유지한 결과다.

실제 프로젝트는 등록된 기존 리소스를 사용했다. 자동 테스트의 도형 이미지/영상은 합성 시험 자료이며 AI 생성 결과로 표시하지 않았다. 외부 AI 생성 요청과 추가 생성 크레딧 사용은 0건이다.
