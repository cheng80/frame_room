# Idle 기준 보행 후보 제작 실험

## 최신 보완: 반대발 후보와 혼합 시안

**반대발 스윙 후보가 있다.** 축소된 정렬 결과의 일괄 `unknown`을 그대로 해석한 것은 불충분했다. raw의 골반-허벅지 연결과 가림을 다시 대조하면 A4/A8은 먼쪽 다리 스윙, B3/B4는 가까운쪽 다리 스윙으로 읽힌다. 독립 검수도 같은 해석이며 확신도는 중간이다. A4와 A8 자체가 서로 반대발인 것은 아니다.

기존 B만 사용한 5컷 시안은 A4/A8을 제외해 이 가능성을 검증하지 못했다. 이를 보완하여 `Walk AB · 반대발 혼합 8컷`을 저장했다. **B1 → B2 → B8 → A8 → B5 → B6 → B4 → B3**, 각 125ms, 1초 주기다. A8과 B3를 반 주기 떨어뜨렸다. 에디터 현재 revision은 **25**이며 기존 동작 6개·원본·정렬은 보존했다. 새 8슬롯은 기존 렌더와 동일하고 잘림은 0px다. 추가 이미지 생성과 유료 호출은 없다.

A8은 반대발 들기 후보지만, 뒤의 B5를 반대발 전방 착지로 확인한 것은 아니다. 접촉 후보 A1/A5/B1/B5/C1/C3의 raw를 비교했을 때 명확히 반대쪽 전방 착지로 판별한 컷은 아직 없다. 따라서 반대발 스윙이 없다는 결론은 정정하며, 혼합 시안의 착지 연결과 완성 보행 여부는 미확정이다.

근거는 `opposite-leg-audit.json` 및 `opposite-contact-review.json`, 저장 기록은 `mixed-leg-results.json`, 정확한 시간 비교는 `mixed-leg-review.html`, 공유용 시안은 `reorders/ab-other-leg-8/preview.gif`다. raw 재검수 전의 불완전한 관측은 최종 보행 판정 근거로 삼지 않는다.

## 결과

실제 GPT 생성 원본 3장(각 8포즈)을 기존 에디터에서 추출·정렬했다. **24개 모두 정지 외형 기준 통과**다. 머리·스카프·견갑·조끼·검·부츠 등 주요 요소와 비슷한 스타일이 유지된다. 미세 픽셀·명암·얼굴 시점·디테일·자연스러운 포즈 차이는 불합격 사유가 아니다.

보행은 아직 확정하지 않았다. A1–A4와 A5–A8은 비슷한 자세의 반복이며, B1/B5도 유사한 접촉 자세다. C는 접촉과 굽힘 자세가 있으나 겹친 다리의 정체성이 명확하지 않다. 외형 통과와 양발 교대 보행의 완성은 별개다. 요청한 포즈 번호를 실제 관측된 보행 단계로 간주하지 않았다. 모든 단계가 미확정인 것은 필요한 자세가 모두 없다는 증명이 아니다.

## 기존 에디터 적용

- 원본 프로젝트 `1ae8af0c-d313-453f-a834-c8bfabbc6ec7`: revision 38, 최종 전체 snapshot 비교에서 변경 없음.
- 검수 복사본 `2b5a85d7-89b5-4211-a19b-0be18dd71aa2`: revision 19. `Walk A/B/C · 정렬 후 검수`에 각 8프레임을 저장했다.
- 실제 raw를 가져와 배경 제거 → 영역 추출 → 묶음 공통 배율 → 앵커 보정을 적용했다. 각 묶음 첫 접촉 자세의 신장을 기존 Idle 94px에 맞추고 64×128 셀에 렌더했다. 자세별 bbox 높이를 같게 만드는 개별 fit은 하지 않았다.
- 배율은 A `94/419`, B `94/416`, C `94/422`다. 발의 좌우 이동에 수평 앵커가 끌리던 문제를 몸통 중심의 지면 투영으로 보정했다. 후보·앵커의 사용 승인은 대기로 보존했다.
- 최종 가시 높이는 A 94–96px, B 93–97px, C 91–98px다. 자세 변화로 남은 높이 차이는 외형 실패가 아니다. 정식 `render_occurrence` 검사에서 24개 모두 캔버스 초과가 0px였다.
- 초기 추출에서 분리된 작은 조각은 원본을 삭제하지 않고 영역에 병합했다. 복사본의 중간 추출 후보 9개는 숨김 상태로 보존했다.

초기에는 에디터 보정 전 크기와 지나치게 엄격한 외형 기준으로 판단했다. 그 결과는 최종 판정에서 제외했다. 최종 비교 화면은 보정 이미지와 `observations-aligned.json`을 함께 사용한다.

## 수정과 검증

프로젝트 엔진의 배경 제거가 실제 생성 원본의 cyan을 지원하지 않아 `auto`/명시적 `cyan` 처리를 추가했다. 공용 sprite-gen 스킬은 수정하지 않았다. `engine-lock.json`에 프로젝트 패치 해시를 반영했다.

- 기존·추가 배경 제거 테스트 16개 통과.
- 당시 후보 선택 회귀 테스트 5개 통과. Python 문법 검사 및 `git diff --check` 통과.
- 엔진 무결성 검사 360파일 통과.
- ego-browser의 같은 TaskSpace에서 실제 에디터 클립 재생을 확인했다. 비교 화면 28이미지 로드와 프레임 이동·재생·정지를 확인했다.
- 전체 루프의 자연스러움, 양발 교대, 실제 지지발의 미끄럼, 게임 실행 모습은 승인하지 않았다. 이미지의 정지 외형 통과를 애니메이션 완성으로 표시하지 않았다.

## 순서 재정렬 실제 적용

사용자의 순서 편집 지적에 따라, 미확정 다리 라벨을 편집의 선행 조건으로 삼지 않고 아래 두 시안을 **기존 에디터에 저장**했다. 정지 단계 분류만으로 보행 불가를 판단하거나 곧바로 재생성으로 넘어가지 않는다.

| 시안 | 원본 B 후보 순서 | 표시 시간 | 전체 주기 |
| --- | --- | --- | --- |
| Walk B · 재정렬 8컷 | B1 → B5 → B2 → B6 → B8 → B4 → B3 → B7 | 각 125ms | 1,000ms |
| Walk B · 재정렬 5컷 | B1 → B2 → B8 → B4 → B3 | 각 200ms | 1,000ms |

8컷은 기존 8개를 모두 한 번씩 쓰는 순서 변경이고, 5컷은 비슷한 B5/B6/B7을 덜어낸 선택·재배열이다. 뒤쪽 회수 B2/B8 → 높은 전방 굽힘 B4 → 전방 하강 B3 → 도달 B1로 잇는 편집 가설이다. 기존 B3→B4처럼 내려온 발을 다시 올리거나, 착지 직전 뒤쪽 회수 자세가 끼던 순서를 바꿨다.

에디터 최종 revision은 **23**이다. 새 13슬롯 모두 기존 후보 렌더와 동일하며 잘림 0px, 기존 동작 4개와 원본 프로젝트 전체 snapshot은 보존됐다. 새로운 이미지 생성 없이 수행했다. ego-browser에서 전후 비교 화면의 재생·정지와 실제 5컷 에디터 재생을 확인했다. 이는 두 편집 시안이 재생된다는 검증이며 완성된 양발 교대의 판정은 아니다.

우선 비교할 시안은 5컷이다. 같은 1초 주기로 비교하는 `reorder-review.html`과 실제 에디터를 열어 두었다. 근거는 `reorder-proposals.json`, 저장 결과와 확인 기록은 `reorder-results.json`, 현재 snapshot은 `editor-project-after-reorder.json`이다. `reorders/b-reduced-5/preview.gif`는 5컷·200ms를 그대로 재생한다. 8컷 GIF는 형식의 시간 단위 때문에 125ms가 120ms로 저장되므로 정확한 속도 비교는 에디터/HTML에서 한다.

후속 판단은 이 재정렬 시안의 발 회수·내딛기·반복 이음새를 먼저 비교한 뒤 한다. 추가 생성은 순서와 표시 시간으로 해결되지 않는 구체적인 부족 자세를 확인한 경우에 검토한다.
