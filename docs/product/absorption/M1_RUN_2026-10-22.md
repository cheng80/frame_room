## 범위와 인수 조건

기존 `generate_video`, `/v1/jobs/{jid}/retry`, checkpoint, 작업 저장·프로젝트 폴더 계약을 재사용한다. M2–M6 구현이나 별도 큐/생성 API를 추가하지 않는다.

1. 최초 제출부터 거절/응답 유실까지 한 job의 외부 POST는 최대 1회다. ID 없는 접수 불명 상태는 재제출하지 않는다.
2. ID 확보 후 429/5xx·연결 실패·잘린/비JSON 응답은 같은 ID를 제한된 backoff와 전체 잔여 시간 안에서 조회한다. 401/403은 인증 안내 후 중단하며 같은 ID의 수동 재개를 보존한다. provider/인증 자동 전환은 없다.
3. 완료 URL 누락·다운로드 오류·잘못된 MP4는 완료로 등록하지 않는다. 검증·해시·원자적 게시 뒤 확정하며 기존 ID에서 회수를 재개한다.
4. 원본 확정 후 중단은 영수증/로컬 파일 검증부터 재개한다. 후처리와 완성 결과 저장 재시도에서 생성·다운로드·처리가 불필요하게 반복되지 않는다.
5. 저장 성공은 별도 출력과 프로젝트 라이브러리·폴더 DB에 동작/프레임/개별 시간이 일치하고 중복이 없는 것으로 확인한다. 저장 실패 시 원본과 완성 결과를 보존한다.
6. 삭제·출력·작업 등록 수명/잠금을 확인하고, 존재 확인과 읽기 사이에 삭제가 끼어드는 강제 실행 순서 회귀로 보호를 입증한다. M0 최초 실패 원인을 확정했다고 표현하지 않는다.
7. 공개 영수증에는 ID·경로 식별·시도 수·중단 이유만 남기고 token·서명 URL·인증 경로를 노출하지 않는다. 사용자 원본·DB·인증·전역 설정·공용 스킬은 보존한다.

## 검증·제약

- 실제 앱 transport를 로컬 HTTP 서버에 연결해 잘린 body·read timeout·비JSON·잘못된 MP4 및 관련 실패 시나리오를 검증한다. 단순 HTTP 함수 mock만으로 완료하지 않는다.
- `postman:api-engineer`와 `api-simulation`을 읽었다. 현재 Postman CLI는 `1.69.0`이며 `postman simulation -h`는 일반 도움말을 반환해 문서의 1.70+ simulation 기능을 지원하지 않는다. 기존 OpenAPI/계약을 재사용하고 로컬 transport 시험을 수행하며, 이 사유만으로 CLI 전역 갱신·workspace 생성·외부 게시를 하지 않는다.
- 시험은 `SPRITE_DATA_DIR` 및 프로젝트 사본을 격리한다. 사용자 자료를 읽기 전 보존 해시를 확보하고 DB를 여는 제품 import보다 먼저 격리를 설정한다.
- 영향 회귀와 전체 필수 검사/웹 빌드, diff 검토를 실시하고 명령·통과/실패/skip·한계를 기록한다. 브라우저가 필요하면 기존 ego TaskSpace만 사용한다.
- 유료 생성·commit/push/PR/merge/배포는 승인 범위 밖이다.
- 컨텍스트 사용률은 현재 도구에 제공되지 않는다. 임의 추정/자동 감시를 주장하지 않으며 인계 직후 같은 기능 경계의 재이관은 반복하지 않는다.
