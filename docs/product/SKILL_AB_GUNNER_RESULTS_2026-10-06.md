- MP4 SHA-256: `90828bce4736255e80527afe2e82528d5f8e6ea9e34deb5b6d7135dcdebf8f56`.

기존 `frame_room.py`에 실험용 셀 크기·방향 인자를 추가했다. 실제 앱 함수로 처리·정규화·마무리·렌더·출력을 호출하지만 DB/worker 접수/UI 프로젝트 승인을 실행한 제품 E2E는 아니다. 생성 원본/사용자 프로젝트/공용 스킬은 덮어쓰지 않았다.

## 동일 입력 보간: 보호 효과와 움직임 대가

같은 fixed cycle **24장 → 32장**, 위상 회전 없이 **원래 1,000ms 유지**. 실제 출력 PNG를 같은 최신 진단기로 재측정했다.

| 항목 | 현재 보간 | 최신 보간 |
| --- | ---: | ---: |
| 실제 중간 프레임 채택 | 24 | 11 |
| 거절 후 가까운 원본 대체 | 0 | 13 |
| 출력의 진단 경고 슬롯 | 12 / 24 | 0 / 24 |
| 최대 dark excess | 1.445% | 0.091% |
| 완전히 같은 인접 프레임 쌍 | 0 | 4 |

나머지 8슬롯은 원본 시각과 일치하므로 중간 프레임 채택 수에 포함하지 않는다. 최신의 반복 쌍은 출력 index `(6,7)`, `(10,11)`, `(22,23)`, `(26,27)`이다. 자체 진단기로 재측정한 값이므로 독립 품질 평가 점수로 쓰지 않는다. 확대 검수에서는 다리 주변의 흐려진 중간 자세를 원본으로 교체하는 차이를 확인했지만, 원본 대체는 매끄러움과 별개의 선택이다.

따라서 **32장으로 강제 변환하거나 보간을 기본으로 켜지 않는다.** 원래 24장·1초 출력을 유지하고 보간을 요청할 때 최신 `bleed`·불량 거절·대체 출처·반복 구간 표시를 함께 적용한다. 거절률이 높으면 원래 프레임 수 결과와 비교할 수 있어야 한다.

별도 최신 정식 `video-cycle-align`은 자동 선택/보정 결과를 입력해 중간 10장 채택·14장 원본 대체, 오른발 시작으로 11칸 회전했다. 원본 hold 1이어서 재촬영 안내는 없었다. 정식 결과는 **32장·1,333ms**로 위의 1초 통제 시험과 다르다. 이 타이밍을 앱에 그대로 가져와 동작을 느리게 만들지 않는다.

기존 jump repair는 양쪽 모두 선택 내부 1번(원본 19번)을 교체했다. jolt는 보정 전 0.1136 → 후 0.1137, 최대 score는 1.4987 → 1.5118로 이 사례에서 지표 개선이 없었다. **jump repair와 새 cycle 보간 거절은 다른 단계**이며 보정 개수만으로 좋아졌다고 판단하지 않는다.

## 색상과 최종 결정

### 사용자 요구 반영: 게임용 걷기는 한 사이클 8~12장

24장은 분석용 원본 주기이며 게임에 모두 넣는 기본값이 아니다. 기존 앱의 실제 `maxFrames=8/12`, `repairMode=off`, `finishMode=gif`로 같은 구간을 재처리했다. 비교는 [8장·12장 전용 뷰어](../../.data/experiments/skill-ab-gunner-20261006/walk-8-12.html)에 있다. 원본 공간 해상도(몸 높이 94px, 셀 96×128)는 그대로이며 프레임 수만 비교한다.

| 결과 | 원본 프레임 index | 한 사이클 시간 |
| --- | --- | --- |
| 8장 | 18,21,24,27,30,33,36,39 | 1,000ms (각 125ms) |
| 12장 | 18,20,22,24,26,28,30,32,34,36,38,40 | 1,000ms (83/84ms) |

두 결과의 각 PNG는 24장 기준의 대응 PNG와 RGBA 완전 동일하다. 실제 출력의 PNG strip·GIF·WebP가 검증을 통과했고 GIF 추가 색 손실도 0이다. GIF의 표시 시간은 포맷 특성상 10ms 단위로 반올림되지만 총 1,000ms는 유지한다. 뷰어는 canonical 시간을 쓴다. 추가 생성 0회, 보간 0회, 끝에 첫 자세 중복 없음. 기본 후보 8장/선택 12장으로 반영 계획을 수정했지만 제품 기본값은 아직 바꾸지 않았다. 수동 핵심 자세 선정이나 모든 입력의 접지 품질까지 입증한 결과는 아니다.

### 선별 이식 판단

실제 기준·원본·출력의 청록 옷/크림 스카프/금색 총을 확인했다. 이번 이미지에는 의도한 노랑·금색 장식이 많으므로 전역 노랑 제거 방식은 부적절하다. 73장 keyed가 동일해 최신 키 제거에 색 복원 이점이 없다는 결론은 반복됐다. 장갑/금속의 모든 프레임을 의미 영역으로 추적한 색 안정성 평가는 이번 범위에 포함하지 않았다. 기존 검사 영상의 변색 해결을 주장하지 않는다.

1. **적용:** WebP exact 저장, 출력 실패 전달, recipe·원본·계보 보존.
2. **보간 사용 시 적용:** `bleed`와 불량 거절, 실제 원본 대체 계보, 반복 구간/거절 수 표시. 기본 보간 OFF와 원본 시간 유지.
3. **진단으로 적용:** 반복 그림·주기 의심·시작 발/미확정, cover stream 선택 보강. 자동 재생성·자동 승인으로 연결하지 않음.
4. **유지/출력 제한:** 현재 GIF 기본, 공통 영역과 편집/출력 계약. 영상 원본 주기는 보존하고 게임용 걷기는 사용자 요구인 8~12장으로 추출한다. 최신 RGBA·32프레임·전체 crop/점 제거 경로를 일괄 기본 적용하지 않음.
5. **보류:** 크기 보정·장비 좌우/체형 명세의 화질 효과, 별도 재질색 유지 기능. 검증 범위를 넘겨 완료로 표시하지 않음.

## 산출물·검증 범위

미디어는 `.data/experiments/skill-ab-gunner-20261006/`에 있고 Git 제외다. `video/request.json`, `checkpoint.json`, `result.json`에 제출 1회와 출처를 기록했다. `analysis/results.json`은 수치, `contact.png`는 같은 구간 확대, `rife-contact.png`는 보간 진단 상위 슬롯, `common-finish/*/provenance.json`은 추가 통제 조건이다. 기존 실험·사용자 프로젝트·서버 상태는 보존했다.

사용자 프로젝트/SQLite 1,182개 파일 해시 불변을 처리 하네스와 최종 비교가 확인했다. 세 모드 모두 실제 잘림/안전여백 오류는 없고, `FRAME_UNAPPROVED`/`ANCHOR_UNAPPROVED`는 의도대로 남겼다. 제품 코드 이식·전체 테스트·프로젝트 E2E·추가 유료 생성·커밋·push는 하지 않았다. Git 상태는 재개 시 `git status --short --branch`, `git log -8 --oneline --decorate`로 확인한다.

ego-browser의 기존 비교 공간(TaskSpace 3)에 새 탭을 열어 HTML 로드·동일 구간/같은 마무리/RIFE 전환·한 프레임 이동·0.25배 재생/정지·원본 750ms 이동을 확인했다. MP4 readyState 4, canvas 96×128·smoothing false, 보간 결과의 추정 원본 이동 비활성, 화면 오류 없음. 뷰어 11개 결과/4개 모드의 내장 데이터가 현재 파일과 일치하는지 재확인했다. 화면 밖 원본 이동 버튼의 native click이 실패해 이후 조작은 ego `page.evaluate()`의 DOM 클릭으로 확인했다. 전체 페이지 screenshot은 시간 초과였으며 분석 PNG는 별도로 직접 검수했다. 이는 제품 에디터 UI E2E를 대신하지 않는다. 상세 기록은 `analysis/browser-check.json`이다.
