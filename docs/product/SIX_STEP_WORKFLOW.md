# 6단계 제작 실행 계약

제작 화면은 자료 준비, 캐릭터 기준, 동작 만들기, 프레임 편집, 결과 확인, 내보내기의 여섯 단계로 구성한다. 수동 승인 단계는 실행 조건에서 제외한다. 이미지·영상 생성은 사용자의 명시적 실행으로만 시작한다.

결과 확인은 현재 편집 동작을 즉시 미리보기로 표시한다. 선택 동작의 저장·설정 조건이 충족되고 현재 저장 버전의 자동 검사에 오류가 없으면 `준비됨`으로 표시하며 내보내기로 진행할 수 있다. 별도 `bake` 파일 생성은 이 단계의 필수 조건이 아니다. 편집·저장 버전 변경·충돌·저장 동기화 대기 중에는 이전 검사로 완료 처리하지 않는다.

## 화면과 진행 상태

| 단계 | 작업 | 준비 조건 |
| --- | --- | --- |
| 1. 자료 준비 | 가져오기 또는 자료 이미지 생성 | 프로젝트에 이미지 자료가 있음 |
| 2. 캐릭터 기준 | 기준 이미지와 고정 특징 저장 | 현재 동작의 연결 기준(동작이 없으면 active 기준, active가 없으면 마지막 저장 기준)과 identity 자료가 있음. 새 동작도 같은 기본 기준에 연결 |
| 3. 동작 만들기 | 이미지·영상 생성 또는 기존 자료 추출 | 동작의 슬롯이 실제 후보를 참조하거나 추출 후보가 있음 |
| 4. 프레임 편집 | 후보·순서·시간·픽셀·크기·발 정렬 | 현재 동작에 슬롯이 있고 저장·설정 게이트를 통과함 |
| 5. 결과 확인 | 즉시 재생, 선택 동작 자동 검사, 선택적 확정 미리보기 | 편집 준비 조건과 현재 저장 버전의 검사 결과가 유효하며 오류가 없음 |
| 6. 내보내기 | 게임용 파일 생성·결과 확인·다운로드 | 현재 동작을 포함한 현재 저장 버전의 성공 atlas/runtime 출력이 있고 미저장·충돌·폴더 저장 보류가 없음 |

상단 탭과 하단 `현재 단계 n / 6`은 `대기`, `작업 중`, `준비됨`, `수정 필요`, `출력 완료`를 표시한다. 탭 방문 횟수로 완료를 기록하지 않는다. 탭 이동은 자유롭고 하단 `다음`은 현재 단계의 준비 조건을 따른다. 탭을 이동해도 열린 입력·선택 상태를 유지하며 프로젝트를 바꾸면 해당 프로젝트의 상태로 다시 시작한다. 키보드 방향키·Home·End로 탭을 이동할 수 있다.

결과 확인의 `캐릭터 기준 수정`, `동작 다시 만들기`, `프레임·시간 수정`, `크기·발 정렬`은 해당 화면으로 돌아가는 동작이다. 이동만으로 수정·저장·재생성을 실행하지 않는다. 자동 검사는 픽셀·경계·구조를 확인하며 얼굴·손·무기의 모양이나 동작의 미술적 품질은 재생·비교로 직접 확인한다.

## 출력 위치와 이력

- 오른쪽 `출력 설정` / `출력 이력` 탭은 선택한 패널에 전체 높이를 사용한다. 패널마다 한 스크롤 영역을 쓰며 탭 전환으로 선택 동작이나 프로젝트 데이터를 바꾸지 않는다.
- 출력 설정의 `자동 저장 폴더`는 프로젝트의 `outputs` 전체 경로다. `프로젝트 폴더 열기`는 기존 로컬 파일 관리자 기능으로 프로젝트 루트를 연다. 실제 출력은 `outputs/<jobId>/<attemptId>/`에 보관하며 각 이력의 `출력 저장 위치`에서 하위 경로를 표시한다.
- 게임용 출력 요청이 접수되면 이력 탭으로 이동한다. 접수 성공은 파일 생성 완료와 별개이며 실제 작업 상태와 결과를 표시한다. 접수 실패 시 설정 화면을 유지한다.
- 기존 exports와 jobs를 `jobId`로 연결한다. 요청 시각은 `createdAt`, 성공 출력의 완료 기록 시각은 `updatedAt`이다. 파일의 실제 수정 시각을 뜻하지 않는다. 브라우저의 시간대로 표시하고 완료 기록 시각, 미완료 항목은 요청 시각을 기준으로 최신순 정렬한다. 시각이 없는 오래된 기록은 `출력 시각 기록 없음`으로 표시한다.
- 최신 이력 하나는 펼쳐 두고 이전 이력은 기본으로 접는다. 접힌 제목에도 출력 ID·상태·저장 버전·완료 시각(없으면 요청 시각)이 남는다. 이전 항목을 펼치면 경로·오류·결과 보기·다운로드를 확인할 수 있다. 최신 실패·진행 중 항목도 펼쳐 표시하며 최신 성공 결과는 별도 배지로 구분한다.
- 저장 버전은 편집 데이터의 버전이며 출력 횟수가 아니다. 같은 버전의 반복 출력도 각각 보존한다. `전체 파일 ZIP 다운로드`는 `bundle.zip` 사본을 브라우저 설정의 다운로드 폴더 또는 저장 대화상자로 저장한다.

## 데이터와 기술 검증

- 기존 `approval`, `review`, `approved`, 승인 시각·검수 사유·체크 값과 모든 저장 revision을 보존한다. 스키마 변경, 일괄 자동 승인, 데이터 마이그레이션 및 새 API는 필요하지 않다. 레거시 `/v1/reference-revisions/{rid}/approve`와 명시적 검수 편집은 기존 동작을 유지한다.
- `generate`의 states/sheet/frame은 프로젝트에 존재하는 기준 연결이 필요하다. `params.referenceRevisionId` 또는 기존 `activeReferenceRevisionId`를 사용하며 `draft`도 유효하다. 기준을 저장하는 것만으로 active 기준을 자동 변경하지 않는다. `scope: asset`은 기존의 무참조 생성 예외를 유지한다. 영상은 선택한 원본이 필요하고, 지정한 referenceRevisionId가 있으면 실제 기준 및 identity 이미지 일치를 검사한다.
- 후보·프레임·앵커·동작의 `pending`은 생성·검사·bake·export를 막지 않는다. export는 동작에 연결된 기준을 사용하며, 출력 성공으로 프로젝트 승인 값이나 저장 revision을 바꾸지 않는다. 생성 결과 등록은 기존 방식으로 새 revision을 추가하되 기존 승인 메타데이터를 보존한다.
- 사용자가 명시적으로 제외한 `review: rejected` 프레임은 최종 출력에서 `FRAME_REJECTED`로 차단한다. 타임라인에서 제거하거나 다시 선택해야 한다. 슬롯을 자동 누락하거나 순서·시간을 변경하지 않는다.
- 몸 기준의 `approved` 체크박스는 선택적 기존 메타데이터다. 실제 topY/bottomY가 유한한 수인지, bottomY > topY인지, 목표 체고·공통 배율이 양수이며 서로 일치하는지 검증한다. 편집 API의 좌표·체고·배율 범위도 유지한다.
- 원본·기준 파일 존재와 해시, 계보, 픽셀/알파, 셀 범위, 변형, 재생 시간, 필수 앵커 및 현재 프레임·그룹 revision 일치는 계속 검사한다. 잘못된 데이터의 최종 출력은 거절하고 기존 원본·출력은 보존한다. 비엄격 미리보기의 `needs_review`는 기존 QA 상태이며 수동 승인 요구가 아니다.

이미지 생성 어댑터도 승인 여부를 검사하지 않는다. identity가 없거나 참조 구조·이미지 파일이 잘못되면 `provider.invalid_reference`로 거절하며, 재생성 대상의 프레임 ID·asset ID·SHA-256 검사와 전송 전 참조 복사본의 해시 확인은 유지한다.

상세 API·저장 형식은 [IMPLEMENTATION.md](../../packages/contracts/IMPLEMENTATION.md)를 따른다. 회귀 시험은 임시 프로젝트와 합성 이미지·모의 provider 전송을 사용하며 사용자 `.data`와 실제 provider를 호출하지 않는다.

## 검증과 남은 작업

2026-10-12 최종 출력 UI 변경에서 웹 **25개 파일·500개 테스트**, TypeScript/Vite 빌드, `git diff --check`를 통과했다. ego-browser에서 실제 기존 프로젝트의 데스크톱·390px 화면, 설정/이력 전환, 키보드 탭 이동과 이전 이력 펼치기, 동일 버전의 출력 순서·시각·경로를 확인했다. 연결 smoke는 API/worker 준비 상태를 확인했다.

승인 없는 실행 변경의 앞선 통합 검증은 **2,380 PASS / 1 SKIP**이며 최종 출력 UI 변경에서 백엔드 검사를 반복하지 않았다. 실제 새 이미지·영상 생성, 새 게임용 출력, 파일 다운로드와 OS 폴더 열기는 최종 UI 검사에서 실행하지 않았다. 이 문서 갱신은 기존 검증 기록과 코드 대조이며 새 실행 결과를 추가하지 않는다.

HTML 사용 설명서 본문은 2026-10-13에 6탭 흐름과 승인 관문 제거를 반영해 갱신했다. 같은 날 화면 캡처 12장도 현재 UI의 실제 화면으로 재촬영했다([갱신 기록](GUIDE_REFRESH_2026-10-13.md)). 2026-10-13 사용자 승인으로 이 변경을 main에 커밋·푸시한다.
