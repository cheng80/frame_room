# 공개 sprite-gen v2.34 반영 결과

> 2026-10-06 자료 정리: 아래 조사·실험의 원본, 비교 결과와 전용 스크립트는 사용자 요청으로 삭제했다. 제품 결정·구현 기록은 보존하며 과거 경로를 현재 실행 가능한 자료로 해석하지 않는다.

2026-10-06 KST. **게임용 걷기를 기본 8장으로 바꾸고, 공개 v2.34의 품질 기술을 프로젝트 전용 엔진과 앱에 연결했다.** 기존 원본·프로젝트·수동 검수 상태를 유지했다. 이번 구현·검증의 신규 이미지/영상 생성 호출은 0건이다.

현재 변경 상태는 `git status --short --branch`, 실제 이력은 `git log -8 --oneline --decorate`로 확인한다. 특정 커밋을 최신이라고 고정하지 않는다. 이 보고서는 기록 시점의 검증 범위다.

후속 완료: 부위 흔들림과 marker 장비 QA도 기존 속성 패널의 **동작 보완·검사**에 연결했다. [후속 구현·검증 기록](CLIP_TOOLS_2026-10-06.md)을 따른다. 아래 자동 시험 수와 엔진/CLI만 연결됐다는 설명은 이 후속 작업 이전의 기록이다.

## 적용된 동작

| 항목 | 앱에서의 동작 |
| --- | --- |
| 게임용 걷기 | 기본 8장, 선택 12장, 직접 4~64장. 한 사이클 원본 시간을 유지하고 줄일 때 중간 그림을 만들지 않는다. 기존 명시 요청·저장 동작을 자동 변경하지 않는다. |
| 보간 보호 | 주기 맞춤의 auto/on/off, 실제 보간 결과의 번짐·검은 경계 검사, 불량 시 가까운 원본 대체. 실제 선택 결과를 프레임 출처에 기록한다. 흔들림 보정은 별도이며 기본 off다. |
| 크기·여백 | 대응 포즈의 크기 변화를 먼저 검사하고 필요할 때만 보정한다. 여백과 색/알파 분리 변환을 적용하고 원본→보정 좌표를 기록한다. |

| 시작 위치 | 방향별 발 판정과 수동 시작 프레임. 프레임·시간을 함께 회전하며 기존 비교 동작을 바꾸지 않는다. 비이족 체형의 좌우 발은 확정하지 않는다. |
| 영상 시간 | 표지 그림을 제외한 영상 stream으로 검사·디코딩·timestamp를 통일한다. 처리 결과의 실제 timestamp로 구간을 제안한다. |
| 생성 명세 | 체형·장비·캐릭터 자신의 좌우를 기준 그림 설명과 영상 요청·묶음 snapshot에 전달한다. 기존 영상 처리에서 원본 방향을 지정할 수 있다. |
| 구도 가이드 | 한 장 이미지 생성에 선택 가능한 로컬 구도 가이드. 사용자 참조 뒤에 `derived-guide`로 추가하고 해시와 실제 전송 프롬프트를 기록한다. 추가 AI 호출은 없다. |
| WebP | 전체 RGBA, 투명 픽셀의 RGB, 중복 슬롯, 가변 시간까지 유지한다. Pillow의 개별 exact 인코딩을 애니메이션으로 묶어 기존 엄격 검사를 통과한다. 외부 바이너리 설치가 필요 없다. |

기본 GIF 마무리와 편집기의 nearest 처리, cyan 키 제거, 등록된 시트의 행 제한, Codex 인증 격리, 접수 불명 요청의 재전송 금지는 보존했다. 엔진 기반 pin은 v2.12.1이고 공개 품질 반영 버전은 v2.34.0이다. `engine/engine-lock.json`의 `qualityVersion`, backport/patch 해시로 이를 구분한다. 과거 산출물의 기반 엔진 식별자를 바꾸지 않는다.

공개 엔진의 공용 resampler, 이미지 준비/알파 판정, 레이어·씬·시트 변환과 관련 의존 모듈도 반영했다. follow-through, marker 기반 장비 QA, 외부 영상용 프롬프트 도우미는 **엔진/CLI 기능**이다. 이를 새 앱 메뉴까지 구현했다고 주장하지 않는다. 비공개 유료 웹 서비스의 서버 코드·품질과 동등함을 입증한 작업도 아니다.

## 실제 영상 재처리

유료 생성 원본을 재사용해 실제 앱 처리·정규화·마무리·출력 경로를 실행했다. 저장소의 사용자 DB 대신 격리된 실험 폴더를 사용했다.

| 입력 | 선택한 원본 구간 (끝 제외) | 결과 | 한 사이클 |
| --- | --- | --- | --- |
| 이전 검사 영상 | 41~69 | 8장, 64×128 | 1,167ms |
| 새 검사 영상 | 17~41 | 8장, 64×128 | 1,000ms |
| 하늘 해적 영상 | 18~42 | 8장, 96×128 | 1,000ms |

- 세 결과 모두 strip/grid PNG, GIF, WebP를 생성하고 포맷별 픽셀·시간 계약을 검증했다. PNG/WebP는 전체 RGBA를 검사했다. GIF는 10ms 단위와 팔레트 제약을 별도 기록한다.
- 하늘 해적의 이전 8장 결과와 새 8장 결과는 **8/8장의 RGBA 픽셀이 동일**하다. 기본 8장 경로에 추가 블러가 생기지 않았다. 모든 캐릭터의 화질 향상을 입증한 수치는 아니다.
- 별도 24→32장 시험에서 실제 프로젝트 RIFE가 중간 그림 11장을 만들고 손상 감지 13장은 원본으로 대체했다. 총 1,000ms를 유지했다. 32장은 보간 보호 검증용이며 게임 기본값이 아니다.
- 하늘 해적 RGBA 8장도 WebP 전체 RGBA 검사를 통과했다. GIF의 반투명/색 손실은 포맷 제약으로 기록했다.
- 세 실제 영상의 크기 변화는 보정 기준 미만이어서 크기 보정을 적용하지 않았다. 크기 보정·padding 경계는 합성/엔진 회귀 시험으로 검증했으며 실제 줌 영상 개선을 실증한 것은 아니다.
- 원래 프로젝트와 공용 SQLite 등 보호 대상 1,182개 파일 및 입력 원본의 해시는 유지됐다. 후보·앵커는 검수 대기다. `FRAME_UNAPPROVED`/`ANCHOR_UNAPPROVED`를 자동 승인으로 숨기지 않았다.

로컬 증거: `.data/experiments/latest-upgrade-20261006/report.json`, `review.html`, 각 사례의 `lineage.json`과 출력. 재실행 도구는 `scripts/skill_compare/verify_upgrade.py`다. 입력 영상/실험 파일은 Git에 없으므로 다른 기기에서는 필요한 폴더를 별도로 복사해야 한다.

엔진 기본 RIFE 실기 시험 1건은 기본 탐색 경로에 도구가 없어 skip했다. 프로젝트 설치 RIFE는 위 실제 24→32장 재처리에서 실행했다. Pillow·Starlette deprecation 경고가 남아 있다.

ego TaskSpace 3의 새 managed 탭에서 격리 프로젝트로 확인했다. 기본 8장/선택 12장, 원본 영상 로딩, 방향 선택·진단 표시, 8슬롯·1,000ms·96×128 캔버스를 확인하고 UI 폼으로 기존 영상 재처리를 제출했다. 수동 시작 index 2가 새 결과에 반영되고 8장/1,000ms를 유지했다. 일부 화면 밖 입력은 native pointer가 가려져 DOM 입력 이벤트로 검증했다. 전체 마우스 여정·전 화면 스크린샷·수동 미술 승인을 완료했다는 뜻은 아니다.

검증 서버는 격리 `SPRITE_DATA_DIR`에서 실행하고 종료했다. 비교 탭에는 서버 없이 열리는 8장 결과 페이지를 남겼다. 기존 사용자 비교 탭은 보존했다.
