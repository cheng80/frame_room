## 목차 강조 수정

목차를 눌러 장으로 이동한 직후에도 강조가 앞 장에 남던 문제를 고쳤다.

- 원인: 이동한 장의 위쪽 끝은 `html`의 `scroll-padding-top`(100px)과 장의 `scroll-margin-top`(데스크톱 92px, 760px 이하 104px)을 더한 192/204px에 멈춘다. `guide.js`는 고정값 `top < 170`으로 현재 장을 골랐으므로, 장 제목이 22~34px 더 올라가야 강조가 바뀌었다. 퀵스타트의 `완료 체크리스트`(`#complete`)는 `section.chapter`가 아니어서 한 번도 강조되지 않았다.
- 수정(`guide.js`의 `position`): 목차 링크가 가리키는 구역을 대상으로, 실제 CSS의 `scroll-padding-top + scroll-margin-top` 위치(+1px)에 닿은 마지막 구역을 현재 장으로 고른다. 화면 크기가 바뀌면 그때의 CSS 값을 다시 읽는다. 문서 끝에서는 뒤쪽 장이 그 위치까지 올라오지 못하므로, 목차·주소로 이동한 장이 화면에 있으면 그 장을, 그 뒤 독자가 스크롤했거나 이동한 장이 없으면 화면에 보이는 마지막 장을 고른다. `hashchange`·`load`에서도 다시 판단한다. 같은 `aria-current="location"`을 모바일 목차 링크에도 붙이고(`guide.css`에 강조 스타일 1줄), 읽기 진행 막대는 그대로 둔다.
- 회귀 테스트 `apps/web/tests/guideToc.test.ts`: 배포되는 `guide.js`를 그대로 실행하고 목차·구역·CSS 값만 흉내 낸다. 192px 착지, 모바일 204px 착지, 문서 끝의 이동한 장 유지와 스크롤 뒤 해제를 검사한다. 수정 전 `position`으로 바꿔 실행하면 3개 모두 실패한다.
- 검증: 웹 전체 테스트 28개 파일·541개 통과, `npm --prefix apps/web run build` 성공(설명서 HTML은 생성기 결과와 바이트 동일, 생성기·HTML 변경 없음). `python3 scripts/package-guide.py`로 ZIP을 다시 만들었고 `testzip()` 이상 없음, 예상 24개 항목, HTML은 다운로드 링크만 뺀 public 원본과 같고 자산 바이트 동일, 로컬 참조 누락 0, public과 `dist/guide`가 같다. ZIP과 `dist`는 `.gitignore` 정책대로 저장소에 올리지 않는 로컬 산출물이다.
- ego 실제 확인(전용 TaskSpace, 정적 서버): 1280×800·500×691·1280×1400에서 두 문서의 모든 목차 클릭(좁은 폭은 모바일 목차, 클릭 뒤 접힘 확인), 뒤로·앞으로, 첫·중간·마지막 장 경계 직전/착지 위치, 앞 장으로 이동한 뒤 수동으로 끝까지 내렸다가 다시 올리기, 초기 주소 해시, 창 크기 변경 148건이 모두 맞았고 진행 막대 값도 일치했다. 1280×1400에서는 `#complete`가 착지선에 닿지 못해 문서 끝 규칙으로 판정했다. 창이 최소화된 환경이라 이 검사는 실제 스크롤 뒤 `scroll` 이벤트를 직접 보내 판정했고, 브라우저가 보내는 `scroll` 이벤트만으로 바뀌는 것은 클릭·위로 스크롤 3건에서 따로 확인했다. 압축을 푼 ZIP을 `file://`로 열어 목차 강조가 바뀌는 것도 확인했다.

## 한계

- 검색은 입력한 문구 그대로 찾는다. 예를 들어 "기본 포함"은 본문의 "기본으로 포함"과 일치하지 않는다.
- 캡처는 데스크톱 1440×1000 기준이다. 좁은 화면에서는 이미지가 작게 보이므로 확대 창을 사용한다.
- 실제 AI 생성, 인쇄/PDF 출력 결과, Windows 브라우저의 `file://` 동작은 확인하지 않았다.
- 독립 검수의 `file://` 캔버스 픽셀 직접 읽기는 브라우저 보안 제한으로 실패했다. 픽셀 비교 통과로 기록하지 않으며, 재생 상태와 표시 프레임 진행 확인과 구분한다.
