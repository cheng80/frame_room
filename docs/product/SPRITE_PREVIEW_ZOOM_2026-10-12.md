# 스프라이트 보기 배율 점검 · 2026-10-12

스프라이트를 확인하는 편집기 화면에 공통 **축소 / 맞춤 / 1:1 / 확대**를 적용했다. `맞춤`은 현재 패널에 맞춘 처음 보기, `1:1`은 원본 1픽셀을 화면 1픽셀로 표시한다. 작은 원본도 맞춤 상태에서 추가 확대할 수 있다. 커진 이미지는 이미지 영역 안에서 스크롤해 확인한다.

보기 배율은 추출 좌표·앵커·부위 선택 좌표·프로젝트 초안·출력 이미지 크기를 변경하지 않는다. 후보와 타임라인 썸네일은 선택하면 확대 가능한 편집 화면으로 연결된다.

비교의 맞춤 배율은 각 원본에 맞춘 크기를 같은 비율로 늘리고 줄인다. `1:1`과 숫자 배율은 원본 픽셀 기준이다. 비교 창에서 프레임을 이동해도 기준 선택과 배율 설정이 유지된다. 네이티브 스크롤바의 표시 여부에 따라 맞춤에 사용하는 가용 크기는 조금 달라질 수 있다.

## 실제 검증

- ego TaskSpace8을 새로 만들고 앱과 보존 예제 검증 탭만 사용했다. 사용자 창·마우스는 사용하지 않았다.
- 위 브라우저 검증 대상에서 확대, 축소, 원본 크기와 패널 맞춤을 확인했다.
- 320px 폭에서 기준 확대창의 버튼이 화면 안에 있고 커진 원본의 가로·세로 끝으로 스크롤할 수 있음을 확인했다.
- 기존 localStorage 전체의 내용 해시가 검증 전후 같았다. 프로젝트 저장·생성 작업을 실행하지 않았다.
- 보존 예제를 사용한 검증은 새 AI 생성이나 새 도구 처리 결과가 아니다. 장비 검사 보드 뷰에는 보존 atlas를 넣어 보기 기능만 확인했다.
- 웹 단위 테스트 24개 파일·461개 테스트 통과. TypeScript 및 프로덕션 빌드, `git diff --check`, ego 서비스 smoke 통과.

실기 모바일·화면리더는 확인하지 않았다. 영상 처리 결과의 모든 조합은 이번 브라우저 검증에 포함하지 않았다.


## 독립 파일 뷰어 실제 파일 입력 추가 검증

- ego TaskSpace10에서 `/#viewer`로 열고, `runtime.json 선택`과 `atlas.png 선택`의 실제 파일 입력에 로컬 파일을 넣었다. 사용자가 사용 중인 TaskSpace9는 조작하지 않았다.
- 입력은 `8방향 성직자 · 복원`의 저장 버전 2, 첫 동작 8프레임을 프로젝트의 기존 `build_bundle`로 별도 검증 폴더에 출력한 파일이다. 원본·저장 프로젝트·브라우저 초안은 수정하지 않았다. 검수 게이트를 강제 승인하지 않은 `strict=False` 보기 검증용 출력이며 정식 승인 출력으로 취급하지 않는다.
- 실제 atlas는 384×480px이며 runtime에 기록된 SHA-256과 일치했다. JSON만 선택한 상태에서는 플레이어가 열리지 않고, PNG까지 선택한 뒤 실제 불투명 픽셀이 있는 캐릭터가 표시됐다.
