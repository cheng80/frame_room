# 조사 완료 후 문서화·구현 핸드오프

현재 상태: 조사 완료 → 제품 문서 9개 검증 → 새 구현 채팅 생성·작업 시작 확인 완료. 최종 기준은 [제품 문서](../product/README.md)다.

구현 채팅: [캐릭터 스프라이트 에디터 구현](codex://threads/01a1008b-21cc-7432-8b2b-4b89b9ef7158). 이하 절차는 완료된 핸드오프 기록이며 앱 구현 완료를 뜻하지 않는다.

## 완료 감지

조사 채팅 `01a1005d-4b8e-703d-a7b5-8a81eb5c801e`, host `durable`을 `wait_threads`로 확인한다. `docs/planning/workflow-state.json`에 마지막 cursor와 상태를 기록한다. 실행 중이라는 이유만으로 완료로 간주하지 않는다. 에러·중단·사용자 입력 요청은 정상 완료와 구별한다.

완료되면 최종 보고와 실제 결과 파일을 읽는다. 출처·코드 분석·검증 결과·미확인 사항을 기존 `RESEARCH.md`, `IMPLEMENTATION_SPEC.md`, `USER_DECISIONS.md`와 대조한다. 근거가 충돌하면 원본 코드/실험 결과로 조정하고 결정 근거를 남긴다. 확인하지 못한 원작 내부 기능은 새 제품 설계와 구분한다.

## 문서 검증

- CLI 입력 없이 전체 흐름을 완주한다는 사용자 요구가 화면·API·구현 단계·테스트에 모두 연결되는지 확인한다.
- 정렬 수치의 출처와 예시 수치를 구분하고 웅크림·긴 무기·공중 자세를 다룬다.
- 승인 원본, 재생성 버전, 공통 배율, 수동 앵커, 큐레이션 반영, 출력 형식의 계약이 문서 사이에서 일치해야 한다.
- 실제 파일·문서 링크와 JSON 예시를 검증한다. 수행하지 않은 테스트와 provider 인증은 완료로 표시하지 않는다.
- 편집기 일부 화면이나 가짜 생성 데모만으로 전체 구현 완료를 선언하지 않도록 핸드오프한다.

## 새 세션 생성

문서가 준비된 뒤 `list_projects`로 현재 `copy_spritegen` 프로젝트를 다시 확인하고 로컬 환경에 새 구현 채팅을 생성한다. 현재 프로젝트 ID는 `cc864052-7f6b-4d12-892c-20ae83c191ec`이며 생성 직전에 목록으로 유효성을 확인한다. 사용자가 새 세션을 명시적으로 요청했으므로 별도 확인을 반복하지 않는다.

새 채팅은 문서를 읽고 프로젝트 내부의 독립 소스에서 실제 앱 구현·실행·검증·발견한 문제 수정을 시작하도록 지시한다. 이름 예시: `캐릭터 스프라이트 에디터 구현`. 기존 조사 채팅을 재지정하거나 같은 파일을 동시에 구현하지 않는다.

중복 방지를 위해 생성 전 `workflow-state.json`의 구현 채팅 ID를 확인한다. 호출 결과가 불명확하면 최근 채팅 목록에서 생성 여부를 확인한 후 처리한다. 성공한 ID를 즉시 기록하고 한 번의 bounded `wait_threads`로 시작 상태를 확인한다. 새 채팅 링크와 생성 directive를 사용자에게 보고하고, 문서화·핸드오프 자동 확인은 완료 처리한다. 구현 완료를 기다리는 별도 자동 추적은 이번 절차에 추가하지 않는다.
