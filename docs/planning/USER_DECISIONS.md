## 목표

`sprite-gen`을 포크하여 React 또는 Next.js 기반 **게임 캐릭터 스프라이트 제작 웹앱**을 만든다. 현재 큐레이션에 치우친 UI를 확장해 기준 이미지 등록부터 생성·배경 제거·프레임 추출·정렬·큐레이션·출력까지 웹 UI에서 완주한다. 기존 Python 처리 엔진과 검증된 기능은 재사용한다.

용사주식회사 캐릭터 제작 노트의 장점을 결합한다. 승인한 외형과 스타일 참조 분리, 몸 비율 유지, 공통 배율과 발 앵커, 동작 검수, 팀 색 아웃라인, 게임용 출력이 핵심이다. 원작 내부 에디터의 미공개 UI나 알고리즘을 확인한 사실로 주장하지 않는다.

## 사용자가 정한 진행 순서

1. mydot이 맡긴 조사 채팅의 결과를 기다린다.
2. 조사 결과와 이 대화의 요구를 합쳐 실제 제작에 사용할 PRD와 설계문서를 완성한다.
3. 문서의 상호 모순과 구현·검증 가능성을 확인한다.
4. **새 구현 채팅을 생성해 문서와 작업 공간을 핸드오프하고 실제 제작을 시작한다.** 사용자가 이 순서와 새 세션 생성을 명시적으로 요청했다.

## 확정 요구

- CLI를 직접 입력하거나 중간 JSON을 수동 수정하지 않아도 전체 흐름을 완료할 수 있어야 한다.
- 앞단 UI에는 외형/스타일 참조, 승인 버전, 고정 특징, 방향, 동작·프레임·프롬프트, 사용 가능한 생성 provider, 실행·진행·실패·취소·재시도를 포함한다.
- 가져온 PNG/시트도 편집할 수 있고 생성 결과는 후보 풀로 연결한다.
- 서기와 웅크림의 체형 비율을 보존한다. 무기 포함 bbox 높이를 몸 체고로 오인하지 않는다.
- 발 기준과 수동 보정을 지원하고, 자동 추정 실패를 검수할 수 있어야 한다.
- 원본·생성 이력·승인 상태를 보존하고 선택·순서·변형을 저장 및 복원한다.
- 미리보기와 최종 PNG/아틀라스/메타데이터가 같은 편집 결과를 사용해야 한다.
- 실제 이미지 처리와 실제 provider 연동 여부를 모의 데이터 실행과 구분해 보고한다.
- 로컬 설치 `/Users/cheng80/.codex/skills/sprite-gen`은 공용 스킬이므로 직접 수정하지 않는다. 프로젝트 내부 포크/독립 소스에서 작업하고 라이선스·고지를 유지한다.

## 조사 결과로 확정할 사항

- React + Vite와 Next.js 중 적합한 프런트엔드 구성 및 선택 근거.
- 포크 기준 버전/커밋과 현재 설치본의 차이, 보존할 수정 내용.
- Python API와 장시간 작업 실행기, 취소·재시도·복구 방식.
- 기존 큐레이션의 통합 수준, 저장 형식과 최종 출력 경로.
- 기존 추출/정규화 단계에서 체형이 바뀌는 위치와 최소 수정안.
- 실제 생성 인증 상태 및 기존 연결로 검증 가능한 범위. 임의로 유료 API로 전환하지 않는다.
