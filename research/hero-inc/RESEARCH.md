# 캐릭터 스프라이트 제작기 조사

조사일: 2026-10-03 KST. 관찰 사실, 개발자 설명, 설계 제안을 구분한다.

## 결론

`sprite-gen`을 포크하여 처리 엔진으로 재사용하고, React 또는 Next.js 웹앱에서 생성 이전 설정부터 결과 출력까지 연결하는 접근이 적합하다. 사용자 요구는 큐레이션 화면뿐 아니라 기준 이미지·프롬프트·생성·배경 제거·추출까지 UI화하는 것이다. 여기에 용사주식회사의 SSOT·정렬·검수 과정을 결합한다.

다만 제작 노트는 내부 편집기의 전체 소스나 완전한 UI 사양이 아니다. 공개 자료로 확인된 처리 규칙을 재현하고, 공개되지 않은 화면·알고리즘은 구현 제안으로 표시해야 한다.

PXF는 이펙트 생성기이므로 본 조사·구현 범위에서 제외한다. 동일 개발자의 다른 도구라는 이유로 캐릭터 제작기의 기능으로 합치지 않는다.

### 제작 노트의 확정 정보

작업은 승인 이미지와 외형 규칙을 고정한 뒤, 그림체 참조와 캐릭터 외형 참조를 분리하는 것으로 시작한다. 8개 키포즈를 6종 동작에 배치하며, 포즈 수와 애니메이션 수는 다르다. 일부 움직임은 같은 포즈에 위치 보정을 적용한다. 이를 새 관절 프레임 생성으로 오해하면 안 된다.

배경 제거 후 연결된 포즈를 분리하고 알파 영역과 발 기준점을 계산한다. 격자 밖의 총구를 단순 등분으로 자르는 문제를 피한다. 아래 표는 공개된 거너 작업 기준이며 모든 캐릭터의 고정 기본값은 아니다.

| 항목 | 공개된 값/규칙 |
| --- | --- |
| 키포즈 | 4열 × 2행, 8개 |
| 동작 | 대기·사격·스킬·피격·전진·후퇴 |
| 예시 동작 | 동작당 6프레임, 페이지 검수 재생은 5fps |
| 정렬 셀 | 512 × 512px |
| 가장자리 / 바닥 여백 | 2px / 18px |
| 발 추정 영역 | 실루엣 아래 12%, 최소 4px |
| 발 측정 알파 임계값 | 16 이상 |
| 발의 가로 기준 | 측정 밴드에서 좌우 유효 픽셀 끝의 중간 |
| 셀 초과 | 필요할 때 최근접 축소, 배율 0.85 미만이면 오류 |
| 아웃라인 예시 | 두께 1.65px, 복제당 불투명도 0.48, 8방향; 모바일 4방향 비교 |

페이지를 조작해 대기는 `377 × 471px`, `scale=1`, `x=128,y=23`, 웅크린 조준은 `329 × 320px`, `scale=1`, `x=113,y=174`를 확인했다. 두 포즈의 기준 바닥은 `y=494`다. **웅크림은 낮아져야 하며 같은 높이로 확대하면 안 된다.** [측정 영역](https://suile-21173.web.app/hero-inc/prompts#sprite-workbench)

공개 코드의 개별 포즈 셀 맞춤과, 다른 경로에서 사용하는 스트립 공통 배율을 구분해야 한다. `320px 셀 / 16px 바닥 여백`은 설명용 예시이며 위 거너 기준과 섞지 않는다. 발에 가까운 총·망토, 이미지에 그려진 체크무늬, 불투명 영역과 몸 체고의 차이를 별도로 검수해야 한다. [정렬 설명](https://suile-21173.web.app/hero-inc/prompts#alignment-recipe)

## 2. sprite-gen 재사용 평가

공식 [저장소](https://github.com/aldegad/sprite-gen)는 Python CLI와 선택형 큐레이션 웹뷰를 제공한다. 이미지 상태 행 생성, 프레임 추출, 실제 알파 처리, 아틀라스/메타데이터와 엔진용 출력이 있다. 로컬 설치의 `SKILL.md`는 2.12.1을 표시하며 CLI 도움말 실행이 성공했다. 설치본과 원격 main이 완전히 동일한지는 검증하지 않았다.

| 이미 있는 능력 | 이번 도구에서의 역할 | 추가 확인 |
| --- | --- | --- |
| `prepare`, `gen`, `gen-set` | 기준 이미지와 상태별 생성 요청 | provider별 인증·실행 계약·취소 동작 |
| `extract`, `cutout` | 프레임 분리와 투명 배경 처리 | 그려진 체크무늬, 복잡 배경, 분리된 장비 |
| `curation` | 후보 풀, 재생 순서, 변형, 미리보기 | 실제 UI와 내보내기 일치 확인 |
| `compose-atlas`, `export-pngs` | 런타임 아틀라스와 최종 프레임 | 최종 수정 상태가 출력에 반영되는지 |
| `inspect-motion`, `inspect`, `preview` | 동작·접지 검수 보조 | 자동 판단 실패를 미확인으로 노출 |

[큐레이션 문서](https://github.com/aldegad/sprite-gen/blob/main/docs/curation.md)에 따르면 편집은 원본 PNG를 덮지 않는 `curation.json`으로 기록한다. 이를 유지하면 되돌리기와 재출력에 유리하다. 이 문서에는 오래된 소개 부분과 더 구체적인 현재 제스처 설명이 함께 있으므로 UI 세부는 실행본을 기준으로 검증한다.

### 반드시 피해야 할 결합 오류

로컬 `docs/sheet-slicing.md`의 `slice-sheet`는 표정·입상 변형 시트를 대상으로 **셀별 높이 정규화**를 설명한다. 문서도 숙인 자세가 커질 수 있음을 명시한다. 캐릭터 애니메이션의 웅크림·피격에 이를 기본 적용하면 제작 노트와 충돌한다.

따라서 `slice-sheet` 결과를 무조건 애니메이션 프레임으로 채택하지 않는다. 기존 추출 단계의 배율 변화를 먼저 점검하고, 별도 정렬 어댑터에서 기준 자세의 공통 배율과 수동 발 앵커를 보장한다. 이미 왜곡된 프레임을 나중에 정렬하는 것만으로 원래 체형이 복구되는 것은 아니다.

## 3. 합쳐서 만들 제품

**기존 엔진은 생성·처리를 담당하고, 새 화면은 승인 기준과 편집 의도를 관리한다.**

권장 화면은 캐릭터 목록, 기준 이미지/스타일 참조, 동작별 후보와 재생 순서, 정렬 캔버스, 실제 크기 미리보기, 검사 결과, 내보내기다. 노드 그래프는 필요하지 않다.

새로 추가할 핵심은 SSOT 버전 관리, 몸 체고와 장비 포함 영역의 분리, 자동/수동 발 앵커, 공통 배율 잠금, 셀 초과 경고, 배경별 알파 검사, 아군·적군 아웃라인, 생성 이력이다. 사용자에게 매번 스크립트 이름을 고르게 하는 대신 하나의 제작 흐름으로 연결한다.

이후 구현 세부와 수용 기준은 [IMPLEMENTATION_SPEC.md](IMPLEMENTATION_SPEC.md)에 있다.

## 4. 남은 불확실성

1. 용사주식회사 내부 캐릭터 편집기의 전체 UI, 저장 형식, 배경 제거 방식, 동작별 보정 테이블은 확보하지 못했다.
2. 현재 설치된 sprite-gen에서 키포즈의 원래 비율이 어디까지 유지되는지 실제 이미지로 검증해야 한다.
3. 애니메이션 자동 생성은 외형·손·무기 보존을 보장하지 않으므로 사람의 승인 단계를 둔다.
4. 모바일, 협업, 원격 저장소, 생성 서비스 직접 과금은 첫 MVP의 필수 범위가 아니다.
5. mydot 작업 전달은 미완료다. 전용 전송 도구가 없고 Codex 앱의 dot 화면 직접 제어는 도구에서 차단했다. 내장 브라우저의 ChatGPT는 로그아웃 상태다. Slack 설정 실패는 별도 연결 문제이며 mydot 직접 대화의 필수 조건은 아니다.

## 5. 이번에 실행한 검증

- 세 원본 링크를 Codex 내장 브라우저에서 열고 실제 내용을 확인했다.
- 제작 노트에서 대기/웅크림의 배율과 기준선을 비교했다.
- 공개된 핵심 배치 코드를 펼쳐 설명용 코드임을 확인했다.
- Threads의 도구 사용 답변과 자체 편집기 답변의 상위 맥락을 확인했다.
- YouTube 일반 영상 목록 8개와 관련 영상 2개의 한국어 자막을 저장했다. 한 영상의 영어 자막 다운로드는 429로 실패했으나 한국어 자막과 메타데이터는 확보했다.
- 설치된 sprite-gen의 CLI 도움말을 실행했다. 생성·배경 제거·내보내기의 실제 품질 검증은 아직 하지 않았다.
- PXF는 별도 구현 채팅임을 확인하고 본 명세에서 제외했다.
