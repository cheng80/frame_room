## 브라우저 smoke — ego 전용

`npm run test:e2e`는 `scripts/ego-smoke.mjs`를 실행합니다. 설치된 macOS `ego-browser` CLI와 실행 중인 ego lite, 사용 허가된 기존 TaskSpace의 managed 탭, 실행 중인 앱/API/worker가 필요합니다. 브라우저·탭 생성, 이동, 종료, 설치, 다른 브라우저 fallback은 하지 않습니다. 기본 TaskSpace는 없으며 부모가 사용 중인 TaskSpace9도 자동 선택하지 않습니다.

아래 환경변수를 실제 허가된 기존 탭에 맞게 설정한 뒤 실행합니다. **다른 작업이 사용하는 TaskSpace에는 실행하지 마세요.**

```sh
# EGO_TASK_SPACE_ID: 허가된 기존 TaskSpace의 숫자 ID
# EGO_PAGE_LABEL: 해당 공간의 기존 managed 탭 라벨 (예: p1)
EGO_TASK_SPACE_ID="$AUTHORIZED_SPACE_ID" EGO_PAGE_LABEL="$AUTHORIZED_PAGE_LABEL" npm run test:e2e
```

- CLI는 `PATH`와 `~/.local/bin/ego-browser`에서 찾습니다. `EGO_BROWSER_BIN`으로 실행 파일 경로, `EGO_SERVER_NAME`으로 기존 named service를 지정할 수 있습니다.
- `SPRITE_TEST_URL`은 로컬 앱 origin이며 기본값은 `http://127.0.0.1:5173`입니다. 탭이 다른 origin이면 이동하지 않고 실패합니다.
- 앱 DOM 렌더링·화면의 서비스 연결 표시와 `GET /v1/health`의 API/worker/engine 상태만 읽습니다. provider 생성, 데이터 변경, 화면 캡처는 하지 않습니다. session token은 출력하지 않습니다.
- CLI/브라우저/탭이 없거나 연결되지 않으면 종료 코드 1로 명확히 실패합니다. 전체 연결 검사 제한은 20초이고 자동 재시도하지 않습니다. 성공은 `EGO_SMOKE_PASS`로 표시합니다.
- 기존 `tests/journey.e2e.ts`와 Playwright 라이브러리는 historical 자료로 보존합니다. `playwright.config.ts`는 직접 실행을 오류로 중단하며 Chromium 실행 경로와 설치 명령은 없습니다. `--grep`/`--project` 등 과거 옵션도 거부합니다.

브라우저 연결 없이 구문만 확인하려면 다음을 사용합니다.

```sh
node --check scripts/ego-smoke.mjs
node --check scripts/ego-smoke-page.mjs
```

빌드 결과물은 `dist/`입니다. 과거 Playwright 캡처와 trace 등 불필요한 검수 자료는 2026-10-05 사용자 요청으로 정리했습니다. 이 smoke는 전체 UI 여정·키보드·독립 뷰어·bitmap parity 검증을 대신하지 않습니다.

## 화면

### 프로젝트 폴더 관리

프로젝트 하나의 원본·편집 이력·작업·출력을 **프로젝트 폴더 하나**에 보관합니다. 새 프로젝트에서 **저장할 부모 폴더 (선택)**의 **폴더 선택**을 누르거나 경로를 직접 입력하면 그 아래 새 프로젝트 폴더를 만듭니다. 비우면 `SPRITE_DATA_DIR/projects/<이름>--<projectId>`가 기본 위치이며 `SPRITE_DATA_DIR` 기본값은 `.data/`입니다.

| 폴더 안의 항목 | 내용 |
| --- | --- |
| `project.json` | 프로젝트 식별 정보와 저장 형식, `project.sqlite3` 위치 |
| `project.sqlite3` | 현재 편집 상태, 모든 저장 이력, 이미지·영상 메타데이터와 작업·출력 기록 |
| `assets/`, `videos/` | 현재 및 과거 이력에서 사용하는 실제 이미지·영상 |
| `jobs/`, `outputs/` | 작업의 접수·재개 정보와 중간 파일, 처리·내보내기 결과 |

리소스 경로는 프로젝트 폴더 기준 상대 경로로 저장합니다. `project.sqlite3`만 복사하지 말고 **하위 폴더를 포함한 전체 프로젝트 폴더**를 복사해야 원본과 출력을 함께 보관할 수 있습니다. 공용 `app.sqlite3`는 앱의 등록 목록·작업 인덱스/캐시이며 프로젝트 폴더와 함께 옮길 필요가 없습니다. 저장 성공은 프로젝트 폴더 반영까지 완료된 상태입니다.

**폴더 저장 보류**는 폴더가 있어도 저장 반영이 아직 끝나지 않았다는 뜻입니다. 폴더 위치·권한·여유 공간을 확인하세요. 앱 인덱스의 보류 기록은 유지되며 로컬 앱 재시작 시 폴더 반영을 다시 시도합니다. 다시 열어 보류 표시가 해제됐는지 확인하고, 저장 충돌이나 남은 초안을 해결한 뒤 복사·이동하세요. 저장 오류 후 서버 상태를 조회해도 로컬 초안과 마지막 저장 확인을 받은 기준 버전은 자동으로 버리지 않습니다.

- **폴더 위치**: 해당 프로젝트 폴더를 macOS Finder 또는 Windows 탐색기에서 엽니다. 목록에서 전체 경로와 연결 상태를 확인할 수 있습니다. 이 버튼은 현재 초안이나 저장 버전을 바꾸지 않습니다.
- **프로젝트 폴더 열기**: 폴더를 선택하거나 전체 경로를 직접 입력한 뒤 **폴더 열기**를 누릅니다. 폴더 안의 `project.json` 또는 `project.sqlite3` 경로도 허용합니다. OS 선택창을 사용할 수 없으면 직접 입력합니다. 저장된 원본·편집 이력·출력이 복원되며 이전 생성 작업을 자동 재실행하지 않습니다.
- **전체 폴더 복사·백업**: 편집을 저장하고 진행 중인 작업이 끝난 뒤 폴더 전체를 복사합니다. 복사본은 같은 프로젝트 ID를 유지합니다. 같은 ID의 다른 폴더가 이미 등록돼 있으면 열기가 거부되므로, 기존 등록을 목록에서 제거한 뒤 복사본을 엽니다. 두 사본을 동시에 작업하려면 **이력·백업 → 새 프로젝트로 복제** 또는 ZIP 백업 복원으로 새 ID를 만듭니다.
- **폴더 이동·이름 변경**: 편집 저장 → 진행 작업 완료 → **목록에서 제거** → Finder/탐색기에서 전체 폴더 이동·이름 변경 → **프로젝트 폴더 열기** 순서로 진행합니다. 원래 위치에 없는 폴더를 앱이 조용히 다시 만들지 않습니다.
- **목록에서 제거**: 등록과 이 브라우저의 해당 프로젝트 초안을 제거합니다. 프로젝트 폴더의 SQLite, 원본·편집 이력·작업·출력 파일은 모두 유지되며 폴더 열기로 다시 등록할 수 있습니다. 미저장 변경은 먼저 저장하세요. 진행 작업이나 저장 버전 충돌이 있으면 제거를 거부하고 초안을 유지합니다.
- **없는 폴더 정리**: 실제 루트 폴더가 없는 등록을 먼저 조회하고 이름·경로를 보여줍니다. 이동 경로나 분리된 외장 디스크를 확인한 뒤 **N개 등록 정리**를 누르면 앱 인덱스와 해당 브라우저 초안을 정리합니다. 실제 파일은 변경하지 않습니다. 대상이 없으면 실행 버튼이 나오지 않습니다. 폴더가 다시 생겼거나 경로·저장 버전·진행 작업 상태가 바뀌면 전체 정리를 거부하므로 **다시 확인**합니다. 폴더 내부의 손상·누락 파일을 고치는 기능은 아닙니다.

### 영상으로 동작 만들기

`AI 동작 생성 → 영상으로 동작 만들기`에서 Grok Pro/Lite 영상을 생성하거나 기존 MP4를 가져옵니다. 기본 3초·480p이며, 한 번 누르면 영상 한 건을 요청합니다. 생성 후 원본 MP4를 보존하고 배경 제거·구간 선택을 거쳐 새 후보와 검수 대기 동작을 등록합니다. `이 동작 편집하기`로 타임라인에 이동합니다.

`기존 영상 처리`의 자동·전체·수동 구간 선택은 추가 생성 없이 MP4를 재사용합니다. 접수 ID가 있는 중단 작업은 기존 요청 조회부터 재개합니다. 접수 불명 요청은 재전송하지 않습니다. Grok Build 로그인만 사용하며 API 키 fallback은 없습니다. 영상·프레임 출처는 ZIP 백업에 포함됩니다. [구현·검증 기록](../../docs/product/VIDEO_EDITOR_INTEGRATION_2026-10-04.md).

게임용 걷기는 **8장 · 기본**을 사용합니다. 더 촘촘한 결과가 필요하면 **12장**, 직접 입력은 4~64장입니다. 프레임 수를 줄여도 한 사이클의 재생 시간은 유지하며 중간 그림을 자동 생성하지 않습니다. 기존 저장 동작과 명시된 요청 수는 바꾸지 않습니다.

- **주기 보간**은 다른 동작에 주기를 맞출 때 적용합니다. 자동은 손상이 감지된 중간 그림을 원본으로 대체하고, 켜기는 RIFE, 끄기는 가까운 원본을 사용합니다. **동작 흔들림 보정**과 별도입니다.
- **시작 발**은 자동 판정의 근거와 함께 표시됩니다. 기존 영상 처리에서 시작 프레임을 직접 지정하면 새 출력의 순서와 시간을 함께 회전합니다. **원본 보기 방향/캐릭터 방향**을 비우면 저장된 설정을 재사용합니다.
- 결과 진단에서 크기 보정·여러 주기 혼입·그림 갱신 빈도·보간/원본 대체 여부를 확인합니다. 경고만으로 새 유료 영상을 요청하지 않습니다.
- **신체 구조**와 **장비와 손**은 기준 그림 설명과 영상 생성 명세에 반영합니다. 예: `quadruped`, `sword:right; shield:left`. 좌우는 캐릭터 자신을 기준으로 합니다.
- 이미지 한 장 생성의 **구도 가이드 사용**은 로컬에서 만든 가이드를 참조 끝에 추가합니다. 추가 생성 호출은 없으며 실제 AI 생성 원본과 구분해 기록합니다.

[v2.34 적용 범위·실제 검증](../../docs/product/LATEST_SKILL_UPGRADE_2026-10-06.md).

선택 동작의 **속성 → 슬롯 → 동작 보완·검사**를 펼치면 두 선택 도구를 사용할 수 있습니다. 편집을 먼저 저장하세요. 두 도구 모두 외부 생성 호출이나 생성 비용이 없습니다.

- **부위 흔들림**: 반복 동작의 첫 슬롯에서 타원을 드래그하거나 좌표를 입력하고 강도·주파수·감쇠를 조절합니다. 전후 미리보기 확인 후 **새 동작으로 저장**하면 원본을 보존하면서 같은 슬롯 수·시간의 검수 대기 동작을 만듭니다. 편집·프로젝트 버전·설정이 바뀌면 다시 미리보기합니다.
- **장비 좌우 검사**: 장비 이름·캐릭터 자신의 좌우·부위·시점·표식 색을 지정합니다. 장비에만 있는 채도 높은 색을 사용하고 필요하면 투명 기준 그림을 선택합니다. 검수판과 의심 슬롯 이동을 제공하며 표식을 찾지 못하면 판단 불가로 표시합니다. 모든 장비를 의미적으로 인식하거나 자동 수정·승인하지 않습니다.

드물게 생기는 원본 영상의 장갑·무기 변색은 별도 색 복원 버튼으로 개발하지 않으며, 필요할 때 GPT 개별 작업으로 처리합니다. [동작 도구 구현·검증](../../docs/product/CLIP_TOOLS_2026-10-06.md), [API 계약](../../packages/contracts/CLIP_TOOLS.md).

가져온 영상에서 칼·손 등에 배경색이 남으면 `색 번짐 판정 기준`에 영상 제작에 사용한 원본 그림을 선택합니다. 기본 `검수 GIF와 같은 색상`은 공통 영역 축소 후 프레임별 팔레트·알파 정리를 실제 PNG 후보에 저장합니다. `반투명 원본 유지`는 공개 엔진 v2.19의 색상/알파 분리 축소를 사용합니다. 원본 MP4, 추출·배경 제거·축소·마무리 PNG는 각각 보존하며 `마무리 전 · 비교용`과 실제 편집 결과를 전환할 수 있습니다.

- 방향은 측면·정면·뒷면·앞/뒤 대각선, 동작은 대기·걷기·달리기·점프·공격·춤·손 흔들기·환호입니다. 시점과 장비 유지 문구를 요청에 반영합니다. `이미지로 만들기 → 영상용 기준 그림 준비`에서 방향·좌우·중간 걸음/대기 자세를 설명에 추가할 수 있습니다. 기존 설명을 보존하고 한 장 요청으로 바꾸며, 실제 생성은 `새 후보 생성`에서 실행합니다. 이후 결과 그림을 영상의 기준 이미지로 선택합니다.
- `동작 흔들림 보정`은 걷기·달리기의 튀는 프레임을 로컬 RIFE로 보간합니다. 기본은 끄기이며 자동 모드는 실행할 수 없으면 사유를 남깁니다. 보간 프레임에는 입력·비율·처리 좌표를 기록합니다.
- `주기를 맞출 동작`은 같은 프로젝트의 반복 동작과 프레임 수·전체 시간을 맞춥니다. 단발/전체 영상에는 적용하지 않습니다. 프로젝트용 RIFE 경로는 `.data/tools/rife`이며 새 기기에서는 별도로 설치합니다. 설치법은 [핸드오프](../../docs/product/HANDOFF.md#2-새-환경에서-실행)를 참고하세요. 보간에는 생성 비용이 들지 않습니다.
- `현재 설정을 묶음에 추가`로 최대 16건을 준비하고 요청 수·총 영상 길이를 확인합니다. 생성 버튼을 누를 때 각 영상을 요청합니다. 묶음은 전체 검증 후 한 번에 접수하며 같은 제출 식별자로 중복 접수를 막습니다.
- 작업 결과에서 GIF·WebP·가로/격자 PNG를 받을 수 있습니다. 저장된 편집을 포함한 최종 내보내기는 동일 bake의 `animations.zip`·`animation-manifest.json`에도 담깁니다. GIF는 10ms 시간 단위와 255색·이진 알파 제한을 기록하며 WebP·PNG는 RGBA를 보존합니다.

### 전체 기능

- 프로젝트 폴더 생성·열기·위치 확인·목록에서 제거·없는 폴더 정리, 복제·ZIP 백업·새 ID 복원, 저장 이력 복원
- PNG/WebP 업로드, 외형·스타일·자세 참조와 기준 승인
- 제공자 capability에 맞춘 생성 옵션과 단일 프레임 재생성 요청
- 배경 제거, whole/grid/components/regions 추출, Aseprite/runtime JSON 영역 가져오기, 수동 영역 병합·제외·되돌리기
- 공통 배율·셀·안전 여백, 몸 landmark 측정, 접지/공중 수동 앵커, 자동 발 후보 계산 및 명시적 초기화
- 후보 승인·숨김, 반복 occurrence·재정렬·복제·교체, 가변 시간, FPS, 이동·변형·펜·지우개, 로컬 undo/redo
- 편집 미리보기·배경·onion skin, 팀 테두리, 체크리스트 검수, 확정 bake·출력 다운로드
- 상태별 작업 센터, 취소 요청·실패 재시도, 외부 접수 불명 안내
- 저장 ACK, 409 비교·초안 재적용, 브라우저 초안 보관

- `/#viewer`: runtime.json+atlas.png를 서버와 프로젝트 DB 없이 읽는 독립 파일 뷰어

## 저장 규칙

편집은 명시적 저장 전 브라우저 초안입니다. 새 clip/occurrence ID는 API가 발급하므로 저장 시 순차 ACK에서 생성 ID를 찾아 후속 편집 명령을 치환합니다. 중간 저장 실패 시 성공한 명령은 기준 snapshot에 반영하고 남은 명령만 초안으로 보존합니다. 숫자 입력은 blur/Enter에서 범위를 확인한 뒤 반영합니다.

정렬·후보 변경은 해당 프레임을 참조하는 동작의 검수만 무효화하고, 테두리 변경은 모든 동작 검수를 무효화합니다. 관련 변경을 먼저 저장한 다음 수동 승인 탭에서 동작별 체크리스트를 확인하고 승인 명령을 별도로 저장합니다. 최종 내보내기의 authoritative 검증은 서버 bake/QA입니다. 빠른 편집 캔버스는 최종 bitmap과 구별하며 최종 미리보기는 서버 atlas bitmap을 사용합니다.

## 검증 범위

`tests/draft.test.ts`는 반복 occurrence 독립성, 빈 타임라인, ID 재매핑, FPS/가변시간, 검수 무효화 및 재생 시간 경계를 검증합니다. `tests/journey.e2e.ts`는 가져오기·export·독립 뷰어·충돌·백업 등을 다루던 historical Playwright 테스트이며 현재 실행 대상이 아닙니다. 현재 ego smoke 범위는 위 연결 검사에 한정됩니다. 실제 provider 성공 여부는 상위 통합 시험에서 별도로 기록해야 합니다.

`tests/projectDeletion.test.ts`와 `tests/projectFolders.test.tsx`는 폴더 선택·직접 입력, 목록 제거 후 재등록, 늦게 도착한 응답 차단, 없는 폴더 사전조회·확인·정리 및 실패 시 초안 보존을 단위 수준에서 검사합니다. 실제 OS 선택창·파일 이동·브라우저 화면 검증은 별도로 수행합니다.

## HTML 사용 설명서

- 퀵스타트: `/guide/` · 상세 설명서: `/guide/manual.html`
- 프로젝트 목록과 에디터의 `사용 설명서`에서 새 탭으로 엽니다.
- `public/guide/content.json`: 기능별 본문, FAQ, 단축키. `scripts/generate-guide.mjs`: 6단계 퀵스타트와 정적 HTML 생성.
- `public/guide/screens/`: 실제 에고 화면 9장. `media/`: 실제 예제 출력 atlas와 재생 좌표. 별도 API 호출 없이 설명서에서만 재생합니다.
- `npm run guide:build`는 HTML을 갱신하며 `npm run build`에도 포함됩니다. 이후 저장소 루트에서 `python3 scripts/package-guide.py`를 실행하면 오프라인 ZIP을 갱신합니다.
- `frame-room-guide.zip`을 풀고 `index.html` 또는 `manual.html`을 열면 서버 없이 본문·이미지·예제가 동작합니다. 에디터로 이동할 때만 로컬 앱이 필요합니다. 인쇄/PDF 버튼은 브라우저의 인쇄 기능을 사용합니다.
- 설명서 체크리스트는 현재 문서 세션에서만 유지하며 프로젝트 승인과 연결하지 않습니다. ‘수동 승인됨’은 승인 버튼으로 기록된 상태이고, 자동 품질 판정이나 자동 후보 추천을 뜻하지 않습니다.
